abstract: Open-world robotic mobile manipulation requires acting in physical environments with only partial information. While recent Large Vision-Language Model (LVLM) agents show strong open-world reasoning capabilities, existing architectures that rely on direct tool calling struggle with geometric uncertainty and thus are limited to fully-observable tabletop environments. In contrast, Task and Motion Planning (TAMP) systems can solve long-horizon tasks under partial observability but incur high computational costs and require closed worlds. We propose \textbf{TAMPAgent}, an agentic planning framework that unifies the reasoning of LVLMs with the structured constraint satisfaction of TAMP systems. We endow an LVLM agent with a belief-space planning model operating over an extensible API of perception, planning, and control tools. The agent formulates a partial task plan composed of parameterized observation and execution actions, which is subsequently completed using classical search algorithms. After extracting the plan's geometric constraints, the agent leverages its tool API to bind valid parameter values, satisfying feasibility requirements and producing an executable motion plan. Upon execution, the agent continuously updates its belief history and repeats this closed-loop process by interleaving observation and manipulation actions. Evaluated across complex household mobile manipulation tasks on Rainbow Y1 and Unitree G1 platforms, TAMPAgent significantly outperforms direct tool-calling agentic baselines, demonstrating that integrating TAMP constraint satisfaction into agentic planning loops is essential for unstructured, partially observable environments.

## What they do
Agents that write code calling robot tools (Code as Policies, CaP) check no geometric constraints before acting; task and motion planning (TAMP) checks them but needs hand-written problems and fully observed scenes. In TAMPAgent a language-model agent writes the problem and plan, and the planner states which constraints tools must certify before anything moves.

## How it works
- **Hybrid beliefs.** Each plan variable (object location, grasp, placement) is a uniform prior, a language hypothesis written by the agent ("behind the penguin"), or a value certified by a tool: a SAM 3 mask, an RGB-D estimate, a GraspGenX grasp or a cuRobo trajectory.
- **Plan, compile, certify.** The planner compiles a plan of detect, pick and place actions into a constraint satisfaction problem. The agent writes a Python graph of tool calls to bind the first action's parameters, which runs only once every constraint is certified.
- **Replan and escalate.** After each action the agent rewrites the problem. When certification fails, it tries other candidates or viewpoints, then another plan, then new hypotheses, for example moving a blocking object first.

## Results
- Simulated RB-Y1, 20 episodes per task: 77.2% absolute success, against 57.2% for CaP and 61.1% for Graph as Policy (GaP).
- On tasks with a blocker: 75% success, against 50% (CaP) and 56% (GaP). With the apple hidden in the fridge or behind a box, it finds the apple in 14 and 13 of 20 episodes; both baselines manage 9 and 10.
- Per simulated minute it uses 19.3k uncached input and 1.75k output tokens, against 20.3k/1.91k for CaP and 27.4k/2.73k for GaP.
- Simulated G1, six tasks: 53.3% absolute success, against 6.7% for CaP. On real robots, three RB-Y1 tasks and one G1 blocker-clearing run are shown as demos.

## Limitations
The guarantees are only as strong as the tools and perception. Without calibrated probabilities, the agent sometimes keeps searching when acting would succeed, which causes most of its timeouts. The action domain is fixed, and certification protects geometric feasibility but not how the agent interprets the task. The real-robot runs report token use, not success rates.
