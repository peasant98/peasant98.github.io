abstract: Robots that work alongside people should be able to use what they have seen when new requests arise. The same experience may later support identifying an object or returning it to its original location, although these uses were unknown during observation. ReuseMem learns to use one visual memory for multiple later manipulation goals. It records visual features independently of future goals, retrieves complementary evidence for each request, and combines it with the current scene through a lightweight action interface. Retrieval is supervised by how well candidate evidence supports expert-action prediction across different current states, linking memory selection to its use in manipulation. Repeated visual features are stored once, and memory computations that remain unchanged during action generation are reused. Experiments on four simulation tasks and two physical scenarios demonstrate reuse of a common recording across different requests. With matched action adaptation, ReuseMem improves joint goal completion on the benchmark tasks by 24.5 percentage points over uniform memory. These findings show that one memory can support multiple later manipulation goals as the scene changes.

## What they do
A robot often sees something before it knows why it will matter: which closed case holds the USB drive, or where a toy stood before it was moved. ReuseMem records one visual memory without knowing the later goals, then reuses that same recording for several different requests, such as picking the right case and later returning it to its recorded origin.

## How it works
- **Writer.** Frozen visual features (16 tokens per frame) go into a memory bank. Near-duplicate frames share one stored appearance but keep their own time entry, so event order is preserved.
- **Reader.** For each request it picks complementary past frames (anchors, references and supports, plus evenly spaced coverage frames) to fill 24 history slots. It is trained by comparing which selections best predict the expert actions across different current scenes for the same goal.
- **Action interface.** A small fusion module and rank-8 modulation layers combine the retrieved frames, 7 recent frames and the current view. They feed a frozen π0.5-based memory policy (MME-VLA) in simulation, or a robot-specific policy on an SO101 arm.

## Results
- Four RoboMME tasks, 200 recordings with two goals each: both goals succeed in 60.5% (Uniform-Memory 36.0%, MemER 20.0%, no memory 5.5%); continuous two-request sequences succeed in 58.0% (Uniform-Memory 35.0%).
- SO101 arm, two scenarios with 20 recordings and three requests each: all three goals succeed in 14/20 in both (Uniform-Memory 9/20 and 12/20), and continuous sequences succeed in 13/20 in both.
- Without retrieval learning, all-goal success drops to 36.5%. Shared storage shrinks the memory bank from 66.38 to 43.98 MiB, and a new request takes 175 ms (MemER: 1,112 ms).

## Limitations
The authors name perceptual correspondence, precise manipulation and the limited range of histories and goals as limitations. Hidden-object swaps stay hard, at 30% all-goal success in simulation.
