abstract: Robotic manipulation often requires remembering visual information that is no longer observable, such as the original location of an object. Existing approaches typically rely on full observation histories, which become redundant over long horizons, or text summaries, which may omit precise visual details. We study visual moment memory, the ability to retain such details from key moments for subsequent manipulation. To support this study, we introduce VMBench, a suite of long-horizon manipulation tasks requiring memory of spatial locations, visual appearances, and their associations. We further propose MomentMem, a hierarchical architecture in which a VLM-based memorizer selects keyframes and an executor predicts actions conditioned on the selected memories. This separation enables us to evaluate memory selection alongside closed-loop task success and to study memorizer generalization independently of the executor. On VMBench, MomentMem achieves 49.9% average success, outperforming the strongest evaluated baseline by 31.7 percentage points. Moreover, we find that the memorizer transfers well to unseen appearances zero-shot. It can also adapt to an unseen task with only a few memory annotations, reaching 43.7% success, close to the 44.3% obtained with full memory supervision. Further experiments show competitive performance on RMBench and improvements in real-robot manipulation. These results highlight the value of retaining sparse visual evidence for memory-dependent manipulation. Our code is available at https://github.com/PKU-VaLuE-Lab/MomentMem.

## What they do
Many manipulation tasks need a detail that was visible only briefly, such as where a cube sat before someone moved it. Full image histories are redundant over long horizons, and text summaries drop exact positions and textures. The authors build VMBench, nine simulated Franka tasks (ManiSkill3) in which success depends on remembering such a moment, and MomentMem, a policy that keeps a few raw keyframes as its memory.

## How it works
- **Memorizer.** Qwen3-VL-4B, fine-tuned to answer yes/no on whether to store the current frame, given recent frames, the frames already stored and the instruction.
- **Segment supervision.** Each piece of evidence is labeled as an interval of frames. Every epoch one anchor frame per interval is the positive, so any valid frame can be learned, and a later frame becomes positive if an earlier one was missed.
- **Scheduled sampling.** Training gradually swaps teacher-forced memory histories for the memorizer's own selections, so it learns to recover from its mistakes.
- **Executor.** pi0.5, trained on the keyframes the frozen memorizer actually selects plus the current observation.

## Results
- VMBench: 49.9% average success, against 18.2% for EventVLA and 7.0% for pi0.5; 99% on Placement Imitation and 93% on Mine Sweeper.
- Unseen room, table and lighting appearances, with the memorizer reused unchanged: 55.2% against 16.3%.
- RMBench: 69.8% against 67.9% for EventVLA.
- Real Franka, 30 trials per task: Placement Imitation 14/30 (pi0.5 3/30, EventVLA 6/30), Explore Cube 17/30 (11/30, 10/30).
- Ablations: single-frame labels drop success by 43.0 points, removing scheduled sampling by 30.9.

## Limitations
The VLM memorizer adds inference cost. The executor still fails to match textures across stored images: it is not the best method on the appearance-matching tasks, and Explore Cube stays at 2% in simulation. VMBench uses one embodiment and a fixed camera setup, and the real-robot tasks need hand-annotated key segments.
