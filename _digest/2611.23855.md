## What they do
RoboBuilder is a benchmark in which coding agents design both a robot and its open-loop motor program from a real inventory of brick-compatible parts, motors and one custom 3D-printed part. Every design that passes in simulation is built by hand and run on a physical copy of its course, and each real failure goes back to the agent as video.

## How it works
- **Tasks.** Ten obstacles, such as a wall, a rope and a seesaw, at three levels. Agents must cross within 30 simulations, then get 30 more plus the printed part, then make the design lighter or faster, and finally build one robot for all ten obstacles.
- **Learned simulator.** A MuJoCo model built from public part data passed 15 designs that all failed for real. Opus 5.5 requested bench tests and fitted the simulator to filmed runs, adding joints that pull apart, slipping gears and per-tyre grip. It predicts 35 of 38 labelled runs.
- **Hardware loop.** Shown its failure video, the agent may make a small simulator change, accepted only if the old design now fails as filmed, then redesigns. The redesign must pass 3 of 5 perturbed simulations before it is built.

## Results
- Agents (Opus 5.5, Sonnet 5.5, GPT-6 Astra, GPT-6.1 Sol) pass 98% of level-1 tasks, 70% at level 2 and 48% at level 3. Random search and a genetic algorithm pass none.
- A single robot for all obstacles crosses at most 60% of them in simulation and 20-60% for real.
- 66% of simulated passes cross the real course (77%, 68% and 42% by level). One round of the loop cuts level-1 and level-2 failures from 18 to 5, taking real success from 73% to 93%.

## Limitations
The simulator is fitted from one fixed camera and bench tests without force data, so some parameters cannot be identified. Each loop correction is fitted to a single failure, and redesigns are retested on the same course, so the loop measures recovery rather than transfer. Robots run open-loop, Light and Fast designs were not built, and each agent ran once per task.
